# 웹 UI 규칙

- 창 모양은 용도마다 하나, 애플 HIG 구분을 따른다: 시트(거래 상세·선택지/안내), 입력 폼(폰 아래·넓은 화면 가운데), 액션 시트(내가 누른 동작의 확인 — 폰은 아래쪽에 떠 있는 카드), 얼럿(예상 못 한 문제만 가운데), 메뉴(값 고르기). 기준 표는 `components/ui/sheet-layout.ts`, `sheet-layout.test.ts`가 고정 — 사용자 지적, 전부 바텀 시트로 바꿨다가 '모든 걸 다 바텀 시트로 만들라고 한 건 아니었다', 이어서 '전문 애플 디자이너로서 생각해'(2026-11-05).
- 바텀 시트(거래 상세·BottomSheet 위젯) 높이는 내용만큼 최대 85%(`SHEET_MAX_HEIGHT`)로 두고, 끌어내려 닫는 손잡이(`SheetHandle`)를 단다 — 폰에서 상세가 화면을 거의 다 덮어 '바텀 시트가 아니다'라고 지적받음(2026-11-05).
- 상세 화면의 설정 값과 목록 필터는 라벨 붙은 드롭다운을 쌓지 않는다. 설정은 설정 앱 스타일 한 줄(이름 기본색·값 회색, 고르는 줄 ⌃⌄·창 여는 줄 ›), 필터는 칩 한 줄로 두고 둘 다 누른 자리 아래 드롭다운(`components/ui/picker-menu.tsx`)으로 고른다 — 사용자 지적, 입력 양식처럼 보여 디자인이 별로라고 함(2026-11-05).
- 누름 요소에는 hover 색과 함께 `active:` 눌림 표시를 둔다 — 폰에는 hover가 없고 웹뷰 탭 하이라이트를 껐다(2026-11-05 최종 검토). `design-scale.test.ts`가 고정한다.
