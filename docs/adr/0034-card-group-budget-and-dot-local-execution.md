# ADR-0034: 두 개인 카드의 합산 예산과 Dot 로컬 실행

- 날짜: 2026-10-28
- 상태: 카드·합산 예산 운영 반영 완료, Dot 환경의 API 연결 진단 중
- 관련: [ADR-0033](0033-finance-identity-and-dot-boundary.md)

## 확인된 사용자 의도

사용자는 삼성카드와 네이버 현대카드를 둘 다 사용하며, 두 카드의 지출을 기존 용돈 한도 하나로 합산하기를 선택했다. 배우자의 현대카드와 공용 토스카드는 이 예산에 포함하지 않는다. 카드사만 바꾸거나 기존 한도를 새 카드에 복제하면 과거 거래가 섞이거나 총 예산이 늘어난다.

## 결정

기존 삼성 카드의 ID·발급사·거래·예산 참조를 보존하고 상품 별칭만 바로잡는다. 본인 현대카드는 별도 등록한다. 문자에 카드 끝번호가 없으므로 번호를 만들지 않고, 출처 구성원과 발급사에 유일한 카드가 일치하는 경우만 연결한다. 검토·중복·제외 상태는 카드 연결과 별개로 유지한다.

예산은 `card_group` 범위와 정렬된 고유 `cardIds` 목록을 사용한다. 기존 단일 카드 예산 ID·월·이름·한도를 보존하고 범위만 두 카드로 정정한다. 단순 구성원 예산으로 바꾸지 않는다. 구성원 기준에는 같은 기기로 수집한 공용 카드 지출도 들어갈 수 있기 때문이다.

등록·범위 변경·새 달 복사 시 같은 가구의 활성·비공용·동일 소유자 카드 2~20개인지 검사한다. 이후 카드 상태 변경으로 과거 예산 범위가 조용히 달라지지 않도록 집계에서는 해당 월의 명시적 카드 목록을 유지한다. 거래의 공개범위·제외 여부·자산 이동·통화·취소 순액은 기존 계산 규칙을 따른다.

범위 정정에는 변경 전 카드 목록을 보내 동시 수정 충돌을 막고, 감사 기록을 같은 트랜잭션에 남긴다. 과거월 범위 정정은 한도 변경을 허용하지 않지만 실지출과 3개월 평균은 다시 계산된다. 적용 전후 월별 결과를 대조한다.

## Dot 실행 경계

`family-finance`는 PC의 로컬 stdio MCP 설정이다. 이 설정이 Dot 클라우드 대화의 직접 도구 목록에 자동 추가되는 것은 아니다. 사용자가 Dot의 PC 연결이 온라인이라고 확인했고, Dot이 만든 로컬 작업에서 실제 Mac 명령 실행까지 확인했다.

도구 검색이 안 되는 상황을 위해 기존 인증 파일과 HTTP API를 사용하는 고정 조회 명령 `check.cjs`를 제공한다. 원문·금액·인증 값을 출력하지 않고 품질 집계만 조회한다. 이 명령은 MCP 서버 등록 검사나 Dot 연결 성공 판정 도구가 아니다. Dot이 실행한 결과까지 확인해야 한다.

최초 Dot 실행은 `API_UNAVAILABLE`로 실패했고 같은 명령은 기존 로컬 실행 환경에서 성공했다. 네트워크 정책·프록시·인증·가구 확인을 구분할 진단이 필요하다. 접근 통제를 낮추거나 클라우드에 인증 파일을 복사해 해결하지 않는다.

## 검증 기준

- 삼성·현대 구분 전후 기존 거래의 카드 ID·수정 시각 외 필드가 유지된다.
- 두 카드만 예산에 포함하고 공용 토스·배우자 카드·미연결 거래를 섞지 않는다.
- 취소 순액·제외된 중복·통화·자산 이동·다른 가족의 비공개 거래 처리와 월 경계가 유지된다.
- 같은 카드 집합의 중복 등록, 다른 소유자 혼합, 범위 동시 변경, 과거 한도 변경을 거부한다.
- 같은 월의 API·화면·알림·AI 요약 경로가 같은 예산 범위를 사용한다. 검증 중 외부 AI를 호출하지 않는다.
- 로컬 성공과 Dot 실행 성공을 별도로 기록한다. 실패를 0건으로 표시하지 않는다.

Memory MCP가 제공되지 않아 이 ADR에 결정과 검토 근거를 남긴다.

## 운영 결과

삼성 카드 별칭을 정정하고 본인 현대카드를 등록했다. 현대 기존 65건과 복구 문자 거래 2건, 삼성 과거 미연결 4건의 카드 연결을 정정했다. 기존 금액·검토·제외 상태는 유지했다. 이후 8~11월 예산 4개의 ID·이름·한도를 보존하며 두 카드 묶음으로 전환했고, 다른 예산 8개와 전체 거래는 변경하지 않았다. 월별 API 사용액과 독립 SQL 집계가 모두 일치했다.

0064 마이그레이션과 API·worker·웹, 모바일 OTA `85e8ce6`를 반영했다. 실제 PG 동시 수정·롤백을 포함한 예산 검증, 합성 모바일 화면과 실제 로컬 MCP의 합산 예산 조회를 통과했다. Dot 재실행은 사용자가 직접 요청하기로 했다. 자세한 기록은 [운영 보고](../operations/finance-dot-2026-10-28.md)에 남긴다.

후속 Dot 실행은 `login/ENOTFOUND`, 프록시 설정 없음으로 실패했다. API 자체 장애나 인증 실패로 뭉뚱그리지 않고 Dot 실행 환경의 이름 해석·네트워크 허용을 확인한다. 반복 학습: 로컬 MCP 등록, Dot의 PC 연결, 로컬 명령 실행, 외부 API 접근은 서로 다른 검증 단계다. 부정확한 도구 안내를 코드나 권한 확대로 덮지 않는다.
