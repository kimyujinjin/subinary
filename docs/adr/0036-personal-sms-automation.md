# ADR-0036: 본인이 승인한 문자 양식의 자동 정리

- 날짜: 2026-10-29
- 상태: 채택, 구현·검증·운영 배포 완료 (2026-10-29)
- 사용자 승인: 파싱 실패 자동 점검과 제한된 자동 적용, 묶음 검토와 승인 규칙 재사용을 진행
- 관련: ADR-0023, ADR-0033, ADR-0035

## 목적

문자 실패 건수를 숨기는 대신 반복 확인과 수정 시간을 줄인다. 같은 양식은 한 번 확인하되
각 문자의 금액·시각·카드 귀속을 다시 검증한다. 모호하거나 의심스러운 문자는 거래로
반영하지 않고 보존한다. 카드 명세서 없이 문자 수집의 완전성을 보장한다고 표현하지 않는다.

## 결정

### 현재 한 건과 반복 적용을 분리한다

사람 검토의 기본은 현재 한 건이다. `reuseForSimilar=true`를 명시적으로 선택한 경우에만
본인의 같은 양식 대기 문자와 이후 수신 문자를 자동 정리할 정책을 저장한다. 원화 승인과
명시적으로 선택한 본인/공용 활성 카드만 정책을 만들 수 있다. 본문에서 추출한 카드와
선택 카드가 유일하게 일치해야 하며, 레시피를 다시 적용한 결과가 확정 값과 같아야 한다.

기존 `card_sms_templates`의 fingerprint 키 공간을 개인 정책과 전역 레시피로 구분한다.
개인 키는 버전·가구·수신 구성원·기존 양식 지문의 해시다. 레시피의 원래 지문은 유지해
원문 양식도 재검증한다. 기존 전역 레시피를 개인의 재사용 승인으로 소급 해석하지 않는다.
명시적 `automationEnabled=true`가 없는 정책은 자동 적용하지 않는다.

정책 중지는 행을 삭제하지 않고 활성 상태와 수정 시각을 바꾼다. 이후 적용은 중단하지만
이미 생성된 거래를 삭제하거나 금액을 변경하지 않는다. 원격 MCP의 `finance:read` 권한도
유지한다. Dot은 본인 문자 묶음의 요약과 웹 검토 경로를 제공하며 실제 확정은 기존 로그인
웹 화면에서 한다. 기존 무기한 읽기 연결에 쓰기 권한을 자동 추가하지 않는다.

### 자동 반영은 서버에서 원자적으로 검증한다

정책에 일치하더라도 단일 원화 승인 금액, 원문의 정확한 날짜·시각, 가맹점, 액션과 금액의
일치, 카드의 소유·식별, 중복을 다시 확인한다. 취소·외화·다중 금액·수신 시각 근사·불명확한
카드·의심 문구는 자동 적용에서 제외한다. 신뢰도 숫자는 진위 확률로 사용하지 않는다.
카드사는 레시피의 복사 값과 새 원문의 명시적 카드사 표기를 대조한다. 금액·날짜·할부는
부분 숫자 추출을 허용하지 않는다. 시각은 한국 시간의 월·일·시·분으로 다시 대조하며,
원문에 연도가 없어 수신 시각보다 7일 넘게 이전이거나 24시간 넘게 미래인 값은 자동 처리하지 않는다.
이는 조회 기간 제한이 아니라 개별 문자에서 연도를 잘못 추측하지 않기 위한 조건이다.

검토 대기 중인 레시피 추출 결과는 `quarantined`로 유지한다. 기존 `pending_review`는
거래에 이미 반영될 수 있으므로 격리 용도로 사용하지 않는다. 거래 생성과 문자 상태 갱신은
같은 DB 트랜잭션에서 실행한다. 적용 직전 원문·정책 버전·정책 활성 여부를 확인하고,
이미 반영된 원본은 다시 반영하지 않는다. 금액 계약의 쓰기 중지 상태를 동일하게 따른다.
일반 수신과 자동 복구는 동일 카드 잠금과 직렬화 가능한 트랜잭션 안에서 중복을 다시 검사한다.
일반 큐 재시도는 사람이 확정한 문자를 다시 해석하지 않는다. 신규 이벤트 버전 비교에는
PostgreSQL 시각의 원래 정밀도를 보존해 JS Date의 밀리초 절삭으로 처리 누락이 생기지 않게 한다.
거래·이벤트 읽기 대조와 감사 기록까지 같은 트랜잭션에 포함하고 COMMIT 성공으로 완료를 판단한다.
커밋 이후 정상 취소나 사용자 수정을 과거 자동 승인의 저장 실패로 오인하지 않는다.

자동 작업은 사람 검토 API를 호출하지 않는다. 자동 적용을 `human_confirmed`로 기록하거나
추출 규칙을 다시 학습시키지 않는다. 별도 유료 모델 API를 호출하지 않고 기존 계산과
승인된 레시피만 사용한다. 본문 지시·링크는 실행하지 않는다. 실패나 보류로 원문을 지우지 않는다.

### 묶음 조회와 실제 완료를 구분한다

묶음은 본인 수신 범위에서 양식 단위로 제공하며 원문을 MCP에 포함하지 않는다. 조회 상한과
잘린 결과를 표시한다. 정책 승인으로 모든 건이 처리됐다고 말하지 않고 이후 거래/문자
결과를 다시 확인한다. 정상 처리, 확인 필요, 정책 중지 상태를 구분한다.

### 일괄 분류의 승인 범위를 바로잡는다

가맹점별 일괄 분류는 과거 거래와 그 변경 이력만 수정한다. 향후 가맹점 규칙·학습 라벨·계보를
묵시적으로 갱신하지 않는다. 단일 분류에서 명시적으로 향후 규칙을 지정하는 기존 경로는 유지한다.

## 검증

정상 원화 승인, 이상 문구, 중복, 취소, 다중 금액, 원문 시각 누락, 다른 구성원/가구,
정책 중지·원본 변경 경합, 재실행, DB 실패 시 원자적 롤백을 검증한다. 운영 입력을 시험용으로
조작하지 않는다. 합성 데이터와 격리 DB로 적용 결과를 확인한 뒤 운영에서는 읽기 검증한다.

2026-10-29 격리 PostgreSQL에서 자동 승격·감사 SQL 실패 롤백·중지·개인/공용 카드·마이크로초
버전 비교·일반 수신과의 실제 두 연결 잠금 경합을 검증했다. 임시 복제 테이블은 원본의
컬럼 제약과 인덱스를 포함하며 FK·트리거까지 복제하는 전체 운영 DB 복제는 아니다.

## 학습 기록

Memory/context7 MCP가 제공되지 않아 기존 ADR을 읽고 이 문서에 결정을 남긴다.
한 건의 사람 확인과 향후 자동 처리 승인은 별개다. 레이아웃 지문과 confidence만으로
진위·소유권·정확성을 보장하지 않는다. 읽기 MCP 연결 성공과 쓰기 동의·예약 실행은 각각 검증한다.
