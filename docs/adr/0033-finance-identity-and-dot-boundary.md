# ADR-0033: 카드 식별과 Dot 금융 도구의 경계

- 날짜: 2026-10-27
- 상태: 2026-10-28 운영 적용 완료, Dot 대화 호출·카드 등록 구분 확인 대기
- 관련: [ADR-0015](0015-mcp-server-over-http-api.md), [ADR-0027](0027-single-transaction-money-contract.md), [MCP 명세](../api/mcp.md)

## 문제와 확인한 근거

가족이 동일한 카드 상품을 사용하는 상황에서 카드사와 카드 끝번호만으로 가구 내 카드를 연결하면 다른 구성원의 개인 카드에 거래가 붙는다. 운영 읽기 집계에서 거래 구성원과 원본 SMS 구성원은 일치했지만, 비공용 카드 소유자와 다른 구성원의 거래 65건(승인 64, 취소 1)이 확인됐다.

등록 정보에도 상품 별칭과 카드사 설정의 불일치가 확인됐다. 본인의 현대카드 상품 별칭이 삼성 카드사로 설정돼 있으나 그 카드에는 삼성 카드사 SMS 이력이 연결돼 있다. 이는 단순 카드 누락 또는 단순 오타로 확정할 수 없다. 카드사를 바로 바꾸면 서로 다른 카드 이력을 합칠 수 있으므로 실제 카드 사용 구분 확인을 기다린다. 사용자·거래 식별자와 개별 금액은 이 문서에 남기지 않는다.

추가로 금융 결과를 대화에서 활용하려면 문자 수집 누락·파싱 실패·미분류·미계산을 숨기지 않아야 한다. 별도 채팅 앱과 유료 모델 라우터를 다시 만드는 대신 Dot과 기존 데이터 API를 연결한다.

## 결정

### 카드 자동연결은 수집 구성원을 포함한다

공통 `resolvePaymentCardLink`가 동일 가구의 활성 카드 중 원본 구성원 소유 카드 또는 명시적 공용 카드만 후보로 삼는다. 후보가 정확히 하나일 때 연결한다. 다른 구성원의 개인 카드만 일치하거나 여러 후보이면 자동 연결하지 않는다.

카드사가 알려진 경우 끝번호만 같다는 이유로 다른 카드사를 연결하지 않는다. 끝번호가 일치하지 않을 때 카드사만으로 재시도하지 않는다. 카드번호 없는 문자도 원본 구성원과 카드사 기준으로 유일한 적격 후보가 있는지 판단한다. 상품 별칭이나 본문 이름으로 소유자를 추측하지 않는다. 모호한 후보는 가장 제한적인 공개범위를 보존하고 검토 대상으로 남긴다.

원본 `memberId`와 거래 `memberId`는 바꾸지 않는다. 카드 미연결 상태의 중복·취소 후보도 같은 구성원으로 제한한다. 명시적으로 연결된 공용 카드는 기존 공용 처리 규칙을 유지한다. 카드 등록 후 소급 연결도 같은 판단 함수를 사용하며 현재 미연결인 거래만 갱신한다.

### 기존 데이터는 근거 있는 연결만 해제한다

운영 정정 계획은 source member와 거래 member가 같고 비공용 카드 소유자만 다른 65건을 대상으로 한다. 다른 카드로 추측 재할당하거나 새 카드를 만들지 않는다. `card_id`와 수정 시각만 바꾸며 금액·상태·중복 표시·취소 부모·공개범위를 유지한다. 승인·취소 체인의 구성원/연결이 다른 경우 자동 정정에서 제외한다.

CLI는 기본 읽기 전용 계획이며 apply에는 계획 체크섬·건수·전체 스냅샷 비교가 필요하다. 변경 전후 감사 JSON을 권한 600으로 보관한다. 트랜잭션 단위로 실행하고 재실행은 이미 적용된 상태를 인식한다. 이미지 롤백과 데이터 정정 복구는 별개다.

### Dot은 대화, family-memory-ai는 사실과 변경을 맡는다

MCP는 기존 API를 사용해 API의 가족·소유권·공개범위를 유지한다. 기본 `finance-readonly`는 조회 9개다. 사용자가 분류 변경을 요청할 때 `finance-review`의 쓰기 3개를 사용한다. `all`은 기억 5개를 더하는 legacy 모드이며 금융 쓰기를 열지 않는다.

금융 경로는 추가 생성 모델·임베딩 호출 없이 기존 집계와 규칙 계산을 사용한다. 기억 검색·읽기는 기존 AI/RAG 비용 경로이므로 기본에 등록하지 않는다. ChatGPT/Dot 구독과 외부 API 과금은 구분한다.

### 결과의 완전성과 수정 범위를 함께 전달한다

품질 조회는 전 기간 집계이며 SMS는 본인 수집분, 거래는 조회 가능한 비제외 내역이다. 겹치는 검토 건수를 합산하거나 카드 문자 집계를 청구서·통장 잔액으로 표현하지 않는다. 정기지출은 비활성, 미계산, 계산 성공 후 0건, 미확정 후보, 사용자 확정을 구분한다. 별도 계산 상태 행이 0건 성공의 시각도 보존한다.

단일 분류는 API의 SQL 조건으로 `expectedCategoryId`를 원자 비교하고 충돌 시 규칙·확정 라벨까지 함께 롤백한다. 일괄 변경은 같은 세션의 10분 미리보기와 재조회가 필요하다. 전송 후 응답 유실은 동일 ID 재전송을 막고 이력을 조회한다. 세션 메모리 방식이므로 재시작을 넘는 영구 중복방지로 과장하지 않는다.

### 연결 인증과 UI는 사용자가 이해할 수 있어야 한다

로컬 로그인 폼으로 인증하고 소유자 전용 파일(600)에 저장한다. 암호화 저장소는 아니다. 앱 내 브라우저의 `Origin: null`은 일회용 토큰과 Host 검사를 만족할 때만 허용한다. Dot 설정에 비밀번호를 복사하지 않는다.

화면은 거래 구성원과 카드 소유자를 구분하고 연결 불일치를 경고한다. 카드 선택에는 소유자·공용 여부·끝번호를 표시한다. 기기 연결 시각과 실제 문자 수집 시각을 분리한다. 문자 수정은 통화·금액·가맹점·시각을 확인할 수 있게 한다.

## 검증과 남은 경계

공통 식별·중복/취소·파서·MCP 회귀 테스트와 합성 UI 검증을 수행했다. 별도 PostgreSQL 복구본에서 새 migration 및 65건 정정을 검증한 뒤 운영에도 적용했다. 기존 510거래에서 카드 연결과 수정 시각 외 모든 열이 보존됐고, 잘못된 개인 카드 연결 65건은 해제됐다. 실패 문자 6건을 결정적 파서로 복구해 승인 거래 2건이 추가됐다. 본인 카드로 재연결하는 작업은 실제 카드 등록 구분 확인 후 진행한다.

실제 로그인, 로컬 stdio 12개 등록, 금융 조회 9종과 신규 quality API 운영 호출을 확인했다. Dot 앱 내부 실제 호출과 휴대폰의 새 OTA 적용은 별도 확인이 필요하다. 자세한 결과는 [운영 기록](../operations/finance-dot-2026-10-27.md)에 있다.

Memory MCP가 제공되지 않아 이 ADR에 결정을 남겼다. 반복 학습: 카드 별칭을 식별 근거로 쓰지 않고, 출처 구성원·카드 소유자·거래 귀속을 분리한다. 빈 결과를 미계산과 혼동하지 않으며, 변경의 응답 유실을 실패 확정으로 취급하지 않는다.

운영 복구 검토에서 추가한 학습: 실패 잡의 수동 재시도는 원본 불변·이전 결과·현재 상태뿐 아니라 라이브러리의 시도 횟수도 대조한다. BullMQ의 카운터 초기화 없이 재실행하면 복구 코드의 시도 제한과 충돌할 수 있어 실제 Redis로 실패 후 재시도를 검증했다. DB 스냅샷의 timestamptz JSON 대조는 복구본과 운영의 TimeZone도 맞춘다. 배포 기동 검증은 개발 환경 대신 실제 서비스 명령과 네트워크 없는 런타임에서 수행한다.
