# 금액 쓰기 도메인 소유권 — 2026-10-30

## 변경 범위

운영 API·worker의 공개 서버 소스와 빌드 입력 각각 835개를 비교해
`9576bf5fa74b271e77ec30d1d6cf58c60ec57c65`와 모두 일치함을 확인했다. 생성 산출물·
설치 의존성·비밀 설정을 비교하거나 전체 이미지의 비트 재현성을 입증한 것은 아니다.
이 기준에 역사 FX 변경만 이식하고, API 거래·수동 입력·사람 검토와 worker 승격의
직접 금액 쓰기를 공통 도메인 명령으로 옮겼다. 파서 유지보수 기능은 포함하지 않는다.

v2는 `TransactionMoneyService`, legacy/shadow의 v1 호환 산술은
`LegacyTransactionMoneyService`가 소유한다. 앱에는 회원·역할·거래 소유자·카드·분류·
공개범위 확인과 응답 마스킹을 남긴다. 비금액 수정은 허용 필드를 명시하며 기존 분류 CAS,
라벨·규칙 저장과 금액 명령의 트랜잭션 경계를 유지한다.

## 검토·삭제와 동시성

- 기존 행의 검토·삭제는 runtime 모드와 별개로 행의 계약 버전 1/2에 해당하는 명령을
  선택한다. 다른 버전은 거부한다. legacy 명령은 v2 행을 수정하거나 연결하지 않는다.
- 승인에 연결된 취소가 있으면 금액에서 파생한 취소 상태가 검토 플래그보다 우선한다.
  부모의 검토 변경은 자식의 독립적인 중복 의심 표시를 지우지 않는다.
- 취소는 순액 0을 유지한다. 명시적인 중복 의심 표시는 보존하고, 이를 해제할 때
  연결된 취소는 approved, 미연결 취소는 pending_review로 남긴다.
- v2 연결 취소 삭제는 남은 원통화 취소 합계로 원화 누계를 다시 계산한다. 따로 반올림된
  취소 행의 원화 값을 빼지 않으므로 1원 경계에서도 원통화·원화 체인이 일치한다.
- 잠금 순서는 정렬된 승인 부모 → 취소다. 잠금 대기 후 부모 관계·종류·가구·버전을
  다시 확인한다. 중복 삭제는 부모를 두 번 복원하지 않는다. 자식이 있는 승인 삭제는 거부한다.
- 서비스가 연 트랜잭션은 명령의 거부 결과도 전체 롤백한다. 외부 트랜잭션은 API/worker가
  거부 결과에 예외를 던져 이벤트·라벨·분류 변경과 함께 롤백한다.

## 검증 경계

아키텍처 스캐너·검사 범위·상한 12를 변경하지 않는다. 제품 코드의 직접 금액 쓰기 12곳을
명령으로 옮겼으며 남는 탐지는 합성 테스트 SQL과 SQL 문자열 검사다. 테스트 경로를
제외하거나 문자열을 쪼개 탐지를 피하지 않는다.

격리 PostgreSQL에서는 실제 두 테이블의 제약·유일키·불변 트리거와 Drizzle, 실제
API·worker 쓰기 래퍼를 연결한다. FX 14개와 추가 금액·동시성 18개, 총 32개 사례를
검증한다. 실제 promote() 진입도 실행하지만 원본 이벤트·카드 귀속·분류는 합성 포트이며
금융 DB 경로만 실제다. 운영 원문이나 거래를 사용하거나 생성하지 않는다. 실제 회원 FK·
전체 Nest/Redis/큐/알림과 운영 거래 발생 검증을 대신하지 않는다.

원시 postgres.js timestamp 값은 Drizzle 설정에 따라 문자열로 반환될 수 있으므로 통합
검증은 null·타입·유효 시각을 확인한 뒤 정확한 ISO 시각을 비교한다.

## 배포와 롤백 범위

기존 [경량 이미지 절차](./finance-dot-2026-10-27.md#경량-이미지-배포안)에 따라 현재
운영 이미지의 Linux 의존성을 유지하고 최종 빌드한 transaction-domain·API·worker
산출물과 승인된 공개 소스만 고정 manifest로 복사한다. 신규 의존성 설치·DB migration은 없다.
빌드 context에 환경·인증·원문·감사 파일을 넣지 않는다. source commit과 정확한 이미지 ID를
외부 배포 영수증에 기록하고 네트워크 없는 후보 이미지 통합 검증을 수행한다.

기존 project directory, prod Compose와 MCP overlay, 기존 env-file 로딩 순서를 유지한다.
정확한 새 이미지 ID의 override로 API·worker만 no-build/no-deps 재생성한다. web·MCP·DB·
Redis·스토리지·예약 작업은 이번 변경 범위에 포함하지 않는다. 기존 이미지 ID와 같은
Compose 순서의 롤백 override를 먼저 확보한다. 반영 결과가 불명확하면 현재 상태부터
확인하고, 이번 반영의 장애면 이전 이미지로 두 서비스만 복원한다.

향후 표준 전체 빌드가 이 커밋을 포함하지 않는 오래된 작업 트리를 사용하면 수정이 빠질 수
있다. 좁은 파서 유지보수는 현재 실행 이미지를 기준으로 하지만, 기존 이미지 영수증이
달라지면 중단될 수 있다. 해당 예약·작업 트리·설정을 이번 작업에서 임의 변경하지 않는다.
