사용자의 후속 배포 지시에 따라 연결관리 화면·API를 배포 준비한다. ## 화면과 갱신 계약

기존 하단 세 탭은 유지한다. 자산의 `자동 연결 관리`와 상단 설정의 연결관리가 `/more/connections`로 이동한다. 한 화면 안에서 신한·토스증권·토스뱅크·국민은행을 선택한다. 파일 가져오기 메뉴와 `/assets/loan-import` 진입은 신한 연결 화면으로 바뀐다. 이미 저장한 기록은 `/assets/loan-records`에서 계속 관리할 수 있으며 해당 화면에는 새 파일 선택이 없다. 기존 가져오기 API나 기록 자체를 삭제하지 않는다.

신한 후보의 등록은 종류(입출금 통장/전세 대출/중도금 대출)와 계좌 끝 네 자리로 한 건을 선택한다. 목록에서 정확히 한 건만 일치해야 하며, 이후 전체 계좌 식별 지문이 바뀌면 갱신을 중단한다. 통장 수집기는 선택하지 않은 계좌의 금액을 읽거나 반환하지 않는다. 전체 계좌번호를 앱 입력·응답·보관 대상으로 삼지 않는다. 법적 명의 일치를 확인해 주는 금융사 응답은 없으므로 본인 계좌 확인은 사용자 진술이다.

통장은 원화의 실제 계좌 잔액(`balanceKind=ledger`)만 보관한다. 실제 화면의 `입/출금 계좌정보` 표와 `계좌명·계좌번호·신규일·최근거래일·잔액(원)·업무` 열을 요구한다. 예적금/신탁·외화·총 잔액 표를 읽지 않으며, 익숙하지 않은 표 이름이나 열에서는 실패로 중단한다. 접근성 이름의 원본 HTML 속성과 실제 금액 추출은 아직 런타임 검증 전이다. 출금 가능 금액·대출 한도·외화 평가액을 대신 사용하지 않는다. 실제 0원과 미조회/null을 구분하고, 음수 잔액도 부호를 보존하는 문자열로 다룬다. 대출 원금과 통장 잔액은 다른 관측 형식이며 끝 네 자리가 같아도 섞지 않는다. 적금·외화 통장·전체 거래내역 및 여러 계좌를 한 번의 은행 로그인으로 일괄 갱신하는 흐름은 이번 확장 범위가 아니다.

아이디·비밀번호의 서버 암호화 보관, 해당 정보로 정상 로그인, 선택한 조회값의 보관, 화면 진입 시 자동 조회를 각각 등록 화면에 명시한다. 채팅의 인증정보를 제품 등록 자료로 자동 복사하거나 소스·테스트에 보존하지 않는다. 사용자 지시에 따른 이번 정상 Computer Use의 일회성 입력은 제품 자격증명 저장·지속 접근 활성화와 별개다. 실제 등록은 본인의 정상 인증된 앱 입력 경로에서 별도로 수행한다. 배우자의 계좌는 배우자의 앱 계정과 동의로 별도 연결한다.

자산 또는 신한 연결 화면을 처음 열 때 순차로 한 번, 또는 사용자가 `새로 조회`를 누를 때만 은행 조회를 시작한다. 같은 은행 아이디 지문은 사용자·가족을 가로질러 직렬화하고 시도 사이를 최소 15분 띄운다. 화면이 닫혀 있어도 반복 조회하는 스케줄러나 백그라운드 자동화는 없다. GET·상태 확인·권한 재확인은 은행 로그인을 시작하지 않는다.

이번 관측은 소유자에게만 보이고 기존 가족 합계에는 포함되지 않는다. 기존 가족 공개 수동 대출을 찾아 자동 덮어쓰지 않는다. 따라서 **이미 공개한 대출의 가족 합계까지 자동 갱신되는 단계는 아직 아니다.** 기존 항목과의 명시적 연결·공유 동의·중복 집계 계약은 별도 구현과 검증이 필요하다. 금액 미확인을 0원으로 표시하지 않으며 원화 정수는 문자열로 보존한다. `capturedAt`은 화면을 읽은 시각이고 은행 잔액 기준일은 미확인/null이다. 기존 교환 형식을 재사용하더라도 자동 관측을 사용자 검토 완료나 은행 서명 데이터로 표현하지 않는다.

## 접근 정보·요청·오류 처리

- 기존 전용 FinanceVault의 AES-256-GCM과 버전별 키를 사용한다. AAD의 공급자 `shinhan_bank`는 토스증권과 분리되며 용도는 credentials만 허용한다. 기존 토스증권의 AAD·키·토큰 동작을 바꾸지 않는다. SMS 장치용 키나 사용자 비밀번호를 암호화 키로 대체하지 않는다.
- 암호화 로그인 자료는 앱 응답에 포함하지 않는다. 실행 자식은 선택된 로그인 자료를 stdin으로만 받으며 argv·환경변수로 전달하지 않는다. DB/JWT/vault 설정은 자식 환경에 전달하지 않는다. 오류 원문·페이지 내용·stderr·스크린샷·trace·storageState를 보관하지 않는다. JS 문자열의 완전한 메모리 소거를 보장하지 않는다.
- 등록 동의의 식별은 연결 ID·소유자·가족·현재 멤버십 회차·동의 시각·문구 버전에 묶인다. 기존 대출용 1번 문구·이력은 보존하고 통장 선택은 2번의 명시 동의가 필요하다. 두 버전 모두 화면을 열 때 조회하는 동의이며, 일일 무인 조회를 허용하지 않는다. 기존 동의를 통장 조회나 일일 조회로 소급 확대하지 않는다. 해제한 행을 다시 살리지 않고 새 등록으로 동의 이력을 남긴다. 단순 로그인 ID 해시는 직렬화용 가명 지문이며 익명 데이터라고 주장하지 않는다.
- 브라우저는 운영자 지정 실행파일과 고정 신한 HTTPS 호스트만 사용한다. 사용자 지정 URL·실행 인자를 받지 않는다. iframe/외부 리소스·추가 인증이 필요해 현재 경로가 실패하면 허용 범위를 조용히 넓히지 않는다. OTP·CAPTCHA·새 약관·낯선 화면은 사람이 정상 경로로 확인해야 한다.
- API 인스턴스당 브라우저 자식 하나만 허용하며 취소 응답 후에도 자식의 종료가 확인될 때까지 새 작업을 받지 않는다. 이는 OS의 하드 메모리 제한이나 다중 API 인스턴스 전체의 자원 상한은 아니다. 실제 런타임 배치와 운영 자원 상한은 활성화 전에 검증해야 한다.
- 요청 claim을 외부 I/O 전에 커밋한다. 같은 request ID는 결과 확인으로 처리하며 로그인하지 않는다. 잠긴 작업을 GET이 해제하지 않는다. 90초 넘는 불명 작업, 잘못된 비밀번호, 추가 인증, 계좌 변경·모호성, 화면 구조 오류는 자동 반복을 막는다. 이전 성공 관측은 오류 시에도 유지한다.
- 해제·탈퇴·viewer 전환·재가입·사용자/가족 삭제 후 operation/version과 권한을 다시 확인해 늦은 결과를 저장하지 않는다. 진행 중 작업에는 중단 신호를 보낸다. 이미 은행에 전달한 로그인까지 취소됐거나 은행 세션이 폐기됐다고 보장하지 않는다. 자식·브라우저가 확실히 종료되는지 실제 런타임 검증은 활성화 전 차단 조건이다.
- 정상 관측도 은행의 로그아웃 링크 실행, 로그아웃 상태, 로그인 화면 복귀를 확인한 뒤에만 반환한다. 로그아웃이 불명확하면 관측을 성공으로 반환하지 않고 `operation_unknown`으로 중단한다. 합성 검사는 이 오류 경로를 포함한다.
- 로그인 폼의 지연 렌더링을 기다리고, 정상 보안 키보드를 빈 상태로 열고 닫는 사전 점검이 끝난 뒤에만 아이디를 입력한다. 공개 로그인 화면에 뒤늦게 나타나는 정확한 `인터넷뱅킹 보안프로그램설치안내`는 은행의 정상 닫기 버튼으로만 닫는다. 이는 소프트웨어 설치·약관 수락·보안 설정 변경이 아니며, 닫은 뒤에도 정상 키보드가 작동하지 않으면 입력 전에 중단한다. 알 수 없는 팝업을 닫거나 화면 가림막을 강제로 제거하지 않는다. 키보드는 은행이 제공한 아이콘으로 열고 실제 표시를 기다린다. readonly·숨김 암호화 필드를 직접 고치거나 키보드를 우회하지 않는다.
- 연결 해제는 현재 연결의 암호화 접근 자료를 NULL로 하고 앞으로의 사용을 중단한다. 과거 관측·백업까지 영구삭제하거나 암호학적 소거를 완료했다는 뜻이 아니다. 관측은 숨겨지지만 보관된다. 보존·삭제 정책과의 정합성은 활성화 전에 확인해야 한다.

## API·스키마와 롤백

모든 경로는 기존 전역 JWT 인증과 `Cache-Control: no-store, private`를 사용한다. 서비스가 현재 가족 멤버십·소유자·가족 ID·정확한 가입 시각을 검증한다. 관리자여도 다른 사람의 연결을 볼 수 없다. 쓰기는 owner/admin/member 역할만 허용한다.

| 경로 | 동작 |
| --- | --- |
| `GET /v1/bank-connections/catalog?householdId=…` | 네 금융사의 실제 준비 상태, 비밀 정보 없음 |
| `GET /v1/bank-connections?householdId=…` | 본인 연결과 마지막 성공 관측, 은행 I/O 없음 |
| `POST /v1/bank-connections/shinhan` | 동의·selector·암호화 로그인 정보 등록, 등록 자체는 은행 로그인 안 함 |
| `POST /v1/bank-connections/:id/refresh` | expectedVersion/requestId 검증, 정상 UI를 통한 선택 입출금 통장 또는 대출 한 건 조회 |
| `DELETE /v1/bank-connections/:id` | 현재 연결 접근 자료 폐기, 자동 조회 중단 |

0068은 `bank_connections`, `bank_connection_snapshots` 두 테이블을 추가한다. 기존 0067 토스증권 테이블에 은행 레코드를 섞지 않는다. snapshot은 pending에서 terminal로 한 번만 전이하며 terminal 수정·삭제를 차단한다. 멤버십·사용자·가족의 철회 트리거는 구버전 앱 롤백에도 DB에 남긴다. API는 두 테이블과 네 활성 트리거가 모두 존재할 때만 기능 준비 상태를 허용한다. 마이그레이션을 모르는 구버전으로 돌아갈 때 테이블을 역삭제하지 않는다. 격리 PostgreSQL에서 실제 0068을 적용하고, 구형 HouseholdService의 탈퇴 경로에서도 DB 트리거가 접근 자료를 폐기하는지 확인했다. 이는 실제 운영 전체 롤백·가동 검증을 대신하지 않는다.
