# 모아 버튼에서 Mac Codex 실행

모아의 신한은행 조회 시작 버튼은 본인 요청을 서버에 저장한다. 연결한 Mac은 HTTPS로 요청을 받아 기존 ChatGPT 로그인으로 Codex App Server를 시작하고, native Computer Use로 은행 화면을 조작한다. 요청문 복사나 Codex 초안의 수동 전송은 사용하지 않는다.

## 최초 연결

Mac에서 기존 Codex 로그인과 Computer Use 권한을 준비한 뒤 `python3 -B tools/mac-bank-runner/install.py`를 실행한다. 생성된 모아 링크에서 정상 로그인한 본인이 ‘연결 해제 전까지 허용’을 누른다. 승인 화면은 연결을 해제할 때까지 버튼으로 요청한 신한은행 조회와 본인 결과 저장만 허용한다고 설명한다. Mac에 생성한 별도 기기 키는 소유자 전용 파일에 보관하고 서버에는 해시만 저장한다. ChatGPT 토큰과 브라우저 쿠키는 모아 서버로 보내지 않는다.

Mac 로그인 시 `cloud.subinary.moa-bank-runner` LaunchAgent가 시작된다. 이는 사용자가 만든 요청의 수신기이며 은행의 일일 조회 예약이 아니다. 기존 일일 예약의 중지 상태는 변경하지 않는다. 모아의 Mac 연결 해제로 실행 권한을 철회할 수 있다.

승인 요청의 `grantMode: until_revoked`는 `grant_expires_at = NULL`로 기록한다. 기존 클라이언트의 모드 생략과 `seven_days`는 최초 승인 시 7일을 유지한다. 기존 본인이 코드로 명시 재승인한 `until_revoked`만 기간을 확대한다. 연결 해제, 회원 제거·조회 권한 상실, 계정·가구 삭제는 기간과 관계없이 접근을 차단한다. 은행·ChatGPT의 정상 인증 유효기간은 이 설정과 별개다.

## 버튼과 인증

모아에서 신한 이용자 ID·비밀번호를 입력하고 별도 저장·전달 동의 후 저장한다. 서버는 전용 FinanceVault의 AES-256-GCM으로 암호화하고 본인·가구·회원 가입 세대·연결한 Mac·버전을 결박한다. 설정 조회에는 저장 여부와 버전만 포함하며 ID·비밀번호·암호문을 반환하지 않는다. 브라우저 저장소에는 쓰지 않고 제출 후 입력값을 지운다. 조회 중에는 변경·삭제를 거절하며, 연결 해제나 회원 권한 상실 시 암호문을 폐기한다.

모아는 연결한 Mac이 온라인이고 로그인 정보가 저장되었을 때 조회 시작 버튼을 활성화한다. 클릭한 요청은 고정 requestId로 저장하므로 중복 클릭이나 같은 ID의 재전송이 다른 은행 로그인을 만들지 않는다. 요청은 10분 뒤 만료되고, 실제 실행을 시작한 뒤 만료되거나 결과가 불명확하면 자동으로 다시 실행하지 않는다. 동일 사용자의 조회 시작 간격은 최소 15분이다.

새 클라이언트는 조회 동의 v2로 요청하고 현재 로그인 정보 버전을 작업에 고정한다. 승인된 해당 Mac이 최초 claim으로 실행 중일 때만 HTTPS로 로그인 정보를 한 번 받을 수 있다. 구형 조회 동의 v1과 기존 작업은 로그인 정보를 전달받지 않는다. 추가 인증 후 이어가기 역시 로그인 정보를 다시 전달하지 않는다. 전달 응답을 잃어도 재시도하지 않는다.

모델은 은행 로그인 화면 확인 후 비밀 인자가 없는 `moa_login`을 호출한다. Mac 입력 중계기는 공식 App Server의 `mcpServer/tool/call`로 동일 native CUA 세션을 사용해 새 AX의 정확한 은행 출처·일반 ID 입력·보안 비밀번호 입력·정상 로그인 버튼을 확인하고 한 번 입력·제출한다. 평문을 모델 프롬프트나 dynamic 도구 응답에 넣지 않으며 실행기의 파일·인자·환경변수·복구 기록에도 쓰지 않는다. 평문은 HTTPS 응답과 해당 로컬 입력 RPC 메모리에 존재한다. 플랫폼 자체의 진단·보존 정책 전체를 통제하거나 메모리 내 불변 문자열의 완전 삭제를 보장한다는 의미는 아니다.

로그인 중계기는 빈 비밀번호 상태에서 시작하도록 정상 은행 로그인 페이지를 새로고침하고 입력 폼을 다시 확인한다. ID는 일반 입력창에 입력하고, 비밀번호는 은행의 정상 가상키보드를 연 뒤 native AX에 표시된 키 이름으로 클릭한다. 각 클릭 전 현재 은행 출처와 키보드를 확인하고 Shift를 누른 뒤에도 새 AX에서 키 인덱스를 찾는다. 은행의 가상키보드에 없는 문자·모호한 키·바뀐 출처는 제출 전에 중단한다. 대문자·소문자·숫자·확인된 특수문자 94개를 지원하며 공백·한글은 추정 입력하지 않는다. 입력 후 가상키보드를 닫고 ID 로그인을 한 번만 제출한다. DOM·내부 암호화 함수·우회 API는 사용하지 않는다.

저장한 정보로 정상 로그인한 뒤 은행이 추가 인증·지원하지 않는 보안 입력을 요구하거나 비밀번호 오류가 나오면 Mac의 정상 은행 화면을 남기고 모아에 인증 대기를 표시한다. 사용자는 은행 화면에서 추가 인증을 마친 뒤 모아의 ‘인증 완료, 계속 조회’를 누른다. 기존 인증정보·인증서 저장소를 읽거나 보안 입력을 우회하지 않는다. 이체·상환·금융상품 약정·정보 변경은 실행 범위에 포함하지 않는다.

## 저장과 권한

지원 항목은 신한은행의 원화 통장 장부 잔액과 전세·중도금 대출의 남은 원금·만기일이다. 출금 가능액과 대출한도를 장부 잔액으로 취급하지 않는다. 전체 계좌번호가 정상 화면에서 확인되지 않으면 추정하여 저장하지 않는다. 로컬 검증기는 계좌번호를 SHA-256 지문으로 바꾸고 본문에서 폐기한다.

서버는 은행 출처, 자료형, 최근 5분 관찰, 최대 20개, 계좌 중복, 정상 로그아웃 확인, 현재 회원 가입 세대, 실행기 철회, 작업 취소 및 claim을 다시 검사한 뒤 한 트랜잭션에 결과를 저장한다. 실행기는 모델의 최종 주장 외에 native CUA 실행 결과와 로그아웃 완료 AX 문구도 확인한다. 실패한 요청은 이전 성공 관찰을 덮어쓰지 않는다. 결과는 본인에게만 표시하며 기존 가족 자산 합계에는 합산하지 않는다. 화면 관찰은 은행이 서명하거나 사용자가 별도 검수한 자료로 표현하지 않는다.

실행 중 취소·철회·시간 초과 시 은행 세션 로그아웃을 보장할 수 없다. 모아는 미완료·결과 확인 필요 상태를 표시하며 Mac의 은행 화면과 정상 로그아웃 여부를 확인해야 한다.

## 대화와 자원

각 실행 단계는 새 임시 Codex 대화에서 처리하고 대화 원문·화면·금액을 로그로 남기지 않는다. 로컬 복구 파일은 소유자 전용이며 완료 응답 유실을 복구하는 동안만 결과를 보관한다. 은행 로그인을 재실행하는 대신 이미 생성한 완료 결과만 재전송한다.

Mac 실행은 기존 `validation_resources.py`의 해시가 일치하는 API 프로필을 사용한다. 1,536MiB RSS 검사·180초 단계 제한·전역 직렬 잠금·소유 프로세스 정리를 유지한다. 각 Codex 단계 자체는 145초 이내로 제한한다. 원본 정책이나 배포의 메모리·디스크 임계값을 변경하지 않는다.

종료 시 실행 중인 turn은 먼저 중단하고 공개 `thread/unsubscribe`를 호출한다. 실행별 `thread_unload_delay_secs=0`을 지정하고 최대 10초 동안 자기 대화의 `thread/closed` 알림을 기다린 뒤 stdin EOF와 기존 종료 절차를 수행한다. 정리 중에는 새 로그인·관찰·승인 요청을 모두 거절하며, 취소된 작업의 heartbeat 실패가 종료 절차를 막지 않도록 종료 프로토콜만 처리한다. [공식 App Server 수명주기](https://learn.chatgpt.com/docs/app-server)와 [설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference)를 기준으로 구현했다.

현재 설치된 Codex의 비금융 실제 검증에서는 구독 해제 응답은 성공했지만 10초 내 `thread/closed` 알림을 받지 못했다. 이를 정상 대화 unload로 보고하지 않는다. 별도로 App Server의 EOF 종료 코드 0과 원본 자원 정책의 `ownedCleanupConfirmed=true`를 확인했다. 알림 수신 여부와 관계없이 원본 소유 프로세스 검증이 정리 성공을 판정하며, 확인되지 않은 잠금을 자동 삭제하지 않는다.

### 실행별 MCP 최소 구성

Mac 실행기는 해당 App Server 자식의 CLI 인수에만 다음 두 설정을 추가한다. 전역 `config.toml`을 쓰거나 로그인 설정을 바꾸지 않는다. `node_repl`과 `family-finance` MCP는 이 은행 조회 경로에서 사용하지 않으며, native `cua_repl/js`와 `moa_login`·`moa_capture`는 유지한다.

```text
-c mcp_servers.node_repl.enabled=false
-c mcp_servers.family-finance.enabled=false
```

설정 방식은 공식 문서의 [실행별 CLI 설정](https://learn.chatgpt.com/docs/developer-commands?surface=cli)과 [MCP enabled 설정](https://learn.chatgpt.com/docs/extend/mcp)에 따른다. 도구 노출 필터만 바꾸는 대신 사용하지 않는 두 서버를 이 실행에서 비활성화한다. 전체 Apps나 플러그인을 일괄 비활성화하지 않는다.

비금융 합성 검증은 같은 native CUA 세션의 직접 RPC와 dynamic tool 처리 중 중첩 RPC, 모델 응답에 합성 비밀값이 없는지를 확인했다. 아래 수치는 공개 자원 영수증에서 읽은 관측값이며 실제 은행 로그인·조회 성공의 증거가 아니다.

| 비금융 구성 | 최대 관측 프로세스 트리 RSS | 관측 소유 PID 수 | 영수증 |
| --- | ---: | ---: | --- |
| 두 설정 추가 전 | 1,115.72MiB | 13 | `resources-native-broker-protocol-43b4c0bc2ef4.json` |
| 두 설정만 추가 | 893.39MiB | 11 | `resources-native-broker-protocol-74c4536d4b98.json` |

첫 실제 요청은 트리 RSS 약 999.64MiB에서 시스템 메모리 압력이 비정상으로 올라 원본 정책이 중단했고 소유 프로세스 정리를 확인했다. 1,536MiB RSS 한도를 넘어서 중단된 사례는 아니다. 이 영수증에는 개별 프로세스 이름·RSS가 없어 특정 MCP를 원인으로 확정할 수 없다. 합성 검증 두 번의 RSS 차이 역시 다른 호스트 부하나 표본 시점의 영향을 배제하지 않으며, 실제 은행 실행의 압력 정상 상태를 보장하지 않는다.

압력 임계값·검사 간격·최소 조회 간격 15분·claim 종료 상태는 유지한다. 실패하거나 결과가 불명확한 claim을 이 설정 변경으로 다시 실행하거나 재로그인하지 않는다. 새 요청은 기존 작업의 종료와 간격 조건을 확인한 뒤 사용자의 새 버튼 클릭으로만 생성한다.

## 독립 스키마

`tools/mac-bank-runner/schema.sql`만 별도로 검토·적용한다. `mac_bank_runner_schema_migrations`에 모듈 버전과 SQL SHA-256을 같은 트랜잭션에서 기록한다. 기존 은행 마이그레이션 0068·0069 및 main Drizzle journal은 변경하지 않는다. main journal의 마지막 시간을 앞당겨 미적용 마이그레이션을 건너뛰지 않도록 `__drizzle_migrations`에 이 모듈을 기록하지 않는다.

v2는 v1 파일을 변경하지 않고 `schema-v2.sql`로 적용한다. 승인된 본인 연결의 만료 시각만 NULL을 허용하도록 모듈의 명명된 scope 제약을 바꾸며 기존 7일 연결이나 로그인 정보를 일괄 갱신하지 않는다. 같은 모듈 journal에 v2 버전·파일 해시를 따로 기록한다.

v3는 별도 `schema-v3.sql`로 암호화 로그인 정보와 작업의 버전·일회 전달 시각을 추가한다. 조회 동의의 명명된 버전 제약만 v1·v2로 확대하고 기존 작업의 동의와 로그인 정보 버전은 변경하지 않는다. 서버의 본인 권한 검사와 DB의 철회·불변성 트리거를 함께 유지한다. 기존 은행 자동화 플래그·0068·0069·주 마이그레이션 journal에는 적용하지 않는다.

## 운영 확인

웹/API 이미지와 OTA 번들을 각각 검증한다. 버튼의 요청 저장, Mac claim, native CUA 실행, 은행 인증 대기, 실제 관찰 저장은 다른 증거다. 합성 관찰의 저장 테스트를 실제 은행 잔액 조회 성공으로 보고하지 않는다. OTA 게시를 휴대폰의 다운로드·적용 확인으로 보고하지 않는다.

2026-11-03 로그인 입력 진단: 저장된 정보가 인터넷뱅킹 ID 로그인용이라는 사용자 확인 뒤, 시험 문자열만으로 기존 `typeText`가 비밀번호 창에 들어가지 않는 현상을 재현했다. 비밀번호 창은 가상키보드를 표시하면서 비활성화되었고, 은행 안내는 키보드보안프로그램이 있어야 일반 키 입력이 가능하다고 표시했다. 정상 가상키보드 키 8개를 클릭하자 마스킹 문자 8개를 확인했다. 이 시험에서는 로그인 버튼을 누르지 않았으며 새로고침으로 시험값을 지웠다. 따라서 실제 은행의 비밀번호 불일치로 확정하지 않는다.

흐름 분석: 모아 `BankStartPanel` → 조회 동의 v2 작업 생성 → 승인된 Mac의 claim → 요청별 임시 Codex와 native CUA → 일회 로그인 정보 전달 → `moa_capture` 검증 → 정상 로그아웃 → `/complete`의 권한·claim 재확인 → `mac_bank_runner_jobs.observations` 저장이다. 결과는 본인 전용 조회 기록이며 가족 자산 합계에 자동 반영하지 않는다.

가상키보드 수정 후 실제 요청은 로그인 정보 전달 전에 실패했다. 실제 실행 디렉터리에서 금융정보를 사용하지 않는 모델→입력기 검사를 하자 native CUA 2회 뒤 입력기의 앱 선택·폼 확인·새로고침·5회 재확인이 실행됐지만, 은행 폼이 준비되기 전에 `unsupported_layout`으로 중단됨을 재현했다. 별도의 직접 입력기 검사에서는 첫 재확인에 폼이 준비되어 통과했으므로 준비 시점에 따른 차이가 있었다. 고정 5회 검사를 12초 동안 새 준비 검사를 시작할 수 있는 방식으로 변경하며, 기존 145초 전체 기한은 연장하지 않는다. 개별 RPC의 응답까지 12초 안에 끝난다고 보장하는 의미는 아니다. 정상 은행 출처와 ID·비밀번호 입력창이 모두 확인되기 전에는 로그인 정보를 받지 않는다.

## 설계 기록

Memory MCP와 context7 MCP는 이 실행 환경에 노출되지 않아 사용할 수 없었다. 공식 OpenAI App Server·MCP 문서와 React 문서를 직접 확인했다. 설계 결정은 이 문서에 보관한다: hosted 모아는 ChatGPT 인증을 소유하지 않고, 본인 계정에 연결한 Mac이 별도 범위의 grant로 나가는 HTTPS 요청만 수행한다. 반복 검토 항목은 ‘대기와 실행과 저장을 구분’, ‘결과 불명에서 은행 재실행 금지’, ‘서버 결과 저장 전 현재 권한 재확인’이다.

공식 문서: [Codex App Server](https://learn.chatgpt.com/docs/app-server), [MCP 설정](https://learn.chatgpt.com/docs/extend/mcp).

## aside repl 엔진 (2026-11-04)

기본 엔진은 `tools/mac-bank-runner/shinhan_repl.py`의 고정 절차이며 모델을 사용하지 않는다. Codex App Server 경로(`codex_phase`)는 폴백으로 남긴다. 실행기 폴더의 `engine` 파일(소유자 전용, 그룹·기타 쓰기 권한 없음)에 `codex`를 쓰면 다음 작업부터 기존 경로를 사용한다. 파일이 없으면 repl이다.

- 통로는 바꾸지 않는다. 기존 heartbeat·claim·1회 로그인 정보 전달·`/complete` 재전송을 그대로 사용하며 컨테이너에는 Aside CLI나 Aside 로그인 정보를 두지 않는다. `aside` CLI는 macOS 전용 바이너리이고 `aside mcp`는 stdio만 지원하며 데몬은 127.0.0.1의 비공개 프로토콜이므로 컨테이너에서 직접 호출하지 않는다.
- 대화형 `aside repl` 세션 하나에 단계마다 한 줄 JS를 보낸다(호출당 120초 제한, 단계별 15~45초, 전체 140초). 원샷 호출은 종료 시 연 탭을 닫으므로 사용하지 않는다. 세션이 연 탭은 세션 종료 때 닫히고, 사용자가 이미 로그인한 탭은 붙기만 하며 남는다(붙은 탭은 `closeTab`으로 닫히지 않는다).
- 순서: 로그인된 신한 탭이 있으면 그 탭을 쓴다(로그인 정보 미사용). 없으면 로그인 화면(`index.jsp#011100000000`)에서 `#ibx_loginId`를 입력하고, `#비밀번호`를 눌러 TransKey 보안키패드를 연 뒤 키 이름으로 ref를 찾아 클릭한다. 클릭마다 마스킹 글자 수를 확인하고 키패드를 닫은 뒤 `#btn_idLogin`을 한 번 제출한다. 예금 그리드 `#grd_list_01_body_table`과 대출 탭의 `#grd_list03_body_table`을 읽고 `#btn_logout` 후 "로그아웃 되었습니다"를 확인한다.
- 비밀번호 문자는 repl 코드에 넣지 않는다. 은행 출처를 확인한 키패드 snapshot의 ref만 클릭 코드에 넣는다. ID는 입력 코드에 포함된다. 마커 시험에서 Aside 데몬 로그·상태 DB·세션 폴더에 repl 코드 본문이 남지 않았다. Aside 서버로 전송되는지는 확인하지 못했다.
- 은행은 로그인 오류·안내를 `alert`가 아닌 WebSquare 모달 레이어(`.w2modal_popupLayer`)로 띄운다(가짜 ID 검증 시험으로 확인). Aside에서는 `page.on('dialog')`도 발생하지 않는다. 레이어 원문 대신 고정 어휘(비밀번호·오류·횟수·추가인증·OTP 등)의 적중만 꺼내 판정한다. 첫 실제 실행(2026-11-04 20:09)은 페이지 전체 문구를 기준선과 비교하던 이전 판정이 이 레이어를 놓쳐 `timeout`으로 끝났다.
- 판정: 로그아웃 버튼은 성공, 1초 이상 유지된 레이어에 비밀번호·ID와 오류·일치·횟수·잠금 등이 함께 있으면 `credentials_invalid`, 그 밖의 레이어나 로그인 화면 이탈은 사람이 확인하도록 `authentication_required`, 25초 동안 변화가 없으면 `timeout`, 화면 구조 불일치는 `unsupported_layout`이다. 판정하지 못한 실패는 실행기 폴더 `diagnostics.log`(0600)에 단계·코드·어휘 적중·hash만 남긴다. 같은 작업에서 재로그인하지 않으며 로그인 후 오류에도 정상 로그아웃을 시도한다. 단계가 제한 시간을 넘으면 세션을 종료하고 로그아웃 미확인 `timeout`으로 끝낸다.
- 'ID 로그인'을 누르면 은행이 먼저 "ID로그인 시에는 이용 가능한 서비스가 제한…" 안내 레이어를 띄우고, [확인]을 눌러야 로그인이 진행된다(두 번째 실제 실행에서 확인). 이 문구("ID로그인"+"서비스가 제한")의 레이어에서만 글자가 정확히 '확인'인 버튼 하나를 최대 2회 누른다. 다른 레이어는 누르지 않고 멈춘다.
- 은행이 로그인 뒤 `onbeforeunload`를 걸어 세션 종료 때 탭이 닫히지 않을 수 있다. 세션이 연 탭은 끝날 때 메인으로 이동해 입력값을 지우고 핸들러를 해제한다. 사용자가 로그인해 둔 탭은 건드리지 않는다.
