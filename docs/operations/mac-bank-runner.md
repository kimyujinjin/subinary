# 모아 버튼에서 Mac 신한 조회

모아의 신한은행 조회 버튼은 본인 요청을 서버에 작업으로 저장한다. 연결한 Mac의 실행기(`tools/mac-bank-runner/worker.py`)가 HTTPS로 작업을 가져가 Aside 브라우저를 `aside repl`(Playwright 호환 JS) 고정 절차로 조작하고(`shinhan_repl.py`), 결과를 서버에 보고한다. 모델은 사용하지 않는다. 컨테이너에는 Aside CLI나 Aside 로그인 정보를 두지 않으며 Mac에 열린 포트도 없다(실행기는 나가는 요청만 한다).

```text
앱 버튼 ─POST /v1/mac-bank-runner/jobs→ API(작업 queued)
Mac 실행기 ─heartbeat·claim(10초 간격, HTTPS)→ API → 로그인 정보 1회 전달
Mac 실행기 ─aside repl→ Aside 브라우저 → bank.shinhan.com → /progress·/complete → API
```

## 최초 연결

Mac에 Aside 앱 로그인과 Aside CLI(`~/.local/bin/aside`)를 준비한 뒤 `python3 -B tools/mac-bank-runner/install.py`를 실행한다. 생성된 모아 링크에서 정상 로그인한 본인이 ‘연결 해제 전까지 허용’을 누른다. 승인 화면은 연결을 해제할 때까지 버튼으로 요청한 신한은행 조회와 본인 결과 저장만 허용한다고 설명한다. Mac에 생성한 별도 기기 키는 소유자 전용 파일에 보관하고 서버에는 해시만 저장한다. 브라우저 쿠키는 모아 서버로 보내지 않는다.

Mac 로그인 시 `cloud.subinary.moa-bank-runner` LaunchAgent가 시작된다. 사용자가 만든 요청의 수신기이며 은행의 일일 조회 예약이 아니다. 코드 갱신은 `python3 -B tools/mac-bank-runner/install.py --upgrade`로 하며 plist와 페어링은 유지된다(실행기·자원 정책·repl 엔진 파일만 교체하고 재시작). 2026-11-04 이전에 설치한 plist는 `--codex` 인자를 넘기지만 실행기는 받기만 하고 쓰지 않는다.

승인 요청의 `grantMode: until_revoked`는 `grant_expires_at = NULL`로 기록한다. 기존 클라이언트의 모드 생략과 `seven_days`는 최초 승인 시 7일을 유지한다. 연결 해제, 회원 제거·조회 권한 상실, 계정·가구 삭제는 기간과 관계없이 접근을 차단한다.

## 버튼과 인증

모아에서 신한 이용자 ID·비밀번호를 입력하고 별도 저장·전달 동의 후 저장한다. 서버는 전용 FinanceVault의 AES-256-GCM으로 암호화하고 본인·가구·회원 가입 세대·연결한 Mac·버전을 결박한다. 설정 조회에는 저장 여부와 버전만 포함하며 ID·비밀번호·암호문을 반환하지 않는다. 조회 중에는 변경·삭제를 거절하며, 연결 해제나 회원 권한 상실 시 암호문을 폐기한다.

모아는 연결한 Mac이 온라인이고 로그인 정보가 저장되었을 때 조회 버튼을 활성화한다. 클릭한 요청은 고정 requestId로 저장하므로 중복 클릭이나 같은 ID의 재전송이 다른 은행 로그인을 만들지 않는다. 요청은 10분 뒤 만료되고, 실행을 시작한 뒤 만료되거나 결과가 불명확하면 자동으로 다시 실행하지 않는다. 조회 간격 제한은 두지 않는다(2026-11-04 사용자 결정). 한 사람의 진행 중 작업은 하나뿐이며, 진행 중에는 연결 화면 '지금 조회하기'와 자산 화면 '다시 조회'(같은 `POST /jobs` 요청)가 로딩 상태로 새 요청을 막고 그 작업을 따라간다.

조회 동의는 v3(2026-11-04, 엔진을 특정하지 않는 문구)다. v2("Mac의 Codex로")는 구버전 앱 요청으로 계속 받는다. 조회 동의 v2·v3 작업만 현재 로그인 정보 버전을 작업에 고정하고, 승인된 해당 Mac이 최초 claim으로 실행 중일 때만 HTTPS로 로그인 정보를 한 번 받는다(서버 검사와 DB 트리거 `guard_mac_bank_job_credential`이 함께 강제). 구형 조회 동의 v1과 이어가기는 로그인 정보를 다시 전달받지 않는다. 전달 응답을 잃어도 재시도하지 않는다.

이체·상환·금융상품 약정·정보 변경은 실행 범위에 포함하지 않는다. 기존 인증정보·인증서 저장소를 읽거나 보안 입력을 우회하지 않는다.

## 조회 절차 (`shinhan_repl.py`)

- 대화형 `aside repl` 세션 하나에 단계마다 한 줄 JS를 보낸다(호출당 120초 제한, 단계별 15~45초, 전체 140초). 원샷 호출은 종료 시 연 탭을 닫으므로 쓰지 않는다. 세션이 연 탭은 세션 종료 때 닫히고, 사용자가 이미 로그인한 탭은 붙기만 하며 남는다(붙은 탭은 `closeTab`으로 닫히지 않는다).
- 로그인된 신한 탭이 있으면 그 탭을 쓴다(로그인 정보 미사용). 없으면 로그인 화면(`index.jsp#011100000000`)에서 은행 출처와 입력칸을 확인한 뒤에만 로그인 정보를 받는다. `#ibx_loginId`에 ID를 입력하고, `#비밀번호`를 눌러 TransKey 보안키패드를 연 뒤 키 이름(`VIRTUAL_KEY_LABELS`, 쉬프트는 토글)으로 snapshot ref를 찾아 클릭한다. 클릭마다 마스킹 글자 수를 확인하고 키패드를 닫은 뒤 `#btn_idLogin`을 한 번만 제출한다. 키패드에 없는 문자·길이 초과는 입력 전에 `credentials_invalid`로 멈춘다.
- 비밀번호 문자는 repl 코드에 넣지 않는다. 은행 출처를 확인한 키패드 snapshot의 ref만 클릭 코드에 넣는다. ID는 입력 코드에 포함된다. 마커 시험에서 Aside 데몬 로그·상태 DB·세션 폴더에 repl 코드 본문이 남지 않았다. Aside 서버로 전송되는지는 확인하지 못했다.
- 'ID 로그인'을 누르면 은행이 "ID로그인 시에는 이용 가능한 서비스가 제한…" 안내 레이어를 띄우고 [확인]을 눌러야 로그인이 진행된다. 이 문구의 레이어에서만 글자가 정확히 '확인'인 버튼 하나를 최대 2회 누른다.
- 은행은 오류·안내를 `alert`가 아닌 WebSquare 모달 레이어(`.w2modal_popupLayer`)로 띄우며, Aside에서는 `page.on('dialog')`도 발생하지 않는다. 레이어 원문 대신 고정 어휘의 적중만 꺼내 판정한다: 로그아웃 버튼은 성공, 1초 이상 유지된 레이어에 비밀번호·ID와 오류·일치·횟수·잠금 등이 함께 있으면 `credentials_invalid`, 그 밖의 레이어나 로그인 화면 이탈은 사람이 확인하도록 `authentication_required`, 25초 동안 변화가 없으면 `timeout`. 같은 작업에서 재로그인하지 않는다.
- 예금은 첫 화면 그리드 `#grd_list_01_body_table`(`계좌번호_view`·`잔액_display`)에서 읽는다. 대출은 계좌 탭 묶음의 '대출'(형제에 '예금/신탁'과 ISA·휴면예금·다른기관계좌가 있는 것만, 메뉴·바로가기의 같은 이름은 제외)을 눌러 `#grd_list03_body_table`에서 읽는다. 대출명에 중도금·전세 중 하나만 있는 대출만 저장한다.
- 로그아웃은 `#btn_logout` 뒤 "로그아웃 되었습니다"로 확인한다. 로그인 후 오류에도 로그아웃을 시도한다. 단계가 제한 시간을 넘으면 세션을 종료하고 로그아웃 미확인 `timeout`으로 끝낸다.
- 은행이 로그인 뒤 `onbeforeunload`를 걸어 세션 종료 때 탭이 남을 수 있다. 세션이 연 탭은 끝날 때 메인으로 이동해 입력값을 지우고 핸들러를 해제한다.
- 추가 인증이 필요하면 세션 탭이 닫히므로, 사용자가 Mac에서 직접 로그인·인증한 뒤 ‘인증 완료, 계속 조회’를 누르면 이어가기 단계가 그 탭에 붙어 조회·로그아웃한다.
- 판정하지 못한 실패는 실행기 폴더 `diagnostics.log`(0600)에 단계·코드·어휘 적중·탭 후보 수·hash만 남긴다. 화면 원문·금액·계좌번호는 남기지 않는다.

## 저장과 권한

지원 항목은 신한은행의 원화 통장 장부 잔액과 전세·중도금 대출의 남은 원금·만기일이다. 전체 계좌번호가 정상 화면에서 확인되지 않으면 저장하지 않는다. 실행기의 `capture()`는 계좌번호를 SHA-256 지문과 끝 4자리로 바꾸고 원본을 폐기한다.

서버는 은행 출처, 자료형, 최근 5분 관찰, 최대 20개, 계좌 중복, 정상 로그아웃 확인, 현재 회원 가입 세대, 실행기 철회, 작업 취소 및 claim을 다시 검사한 뒤 한 트랜잭션에 결과를 저장한다. 실패한 요청은 이전 성공 관찰을 덮어쓰지 않는다. 결과는 본인 자산에 표시되며, 가족 합계에는 연결 계좌 공유 동의(별도)를 한 경우에만 들어간다.

실행 중 취소·철회·시간 초과 시 은행 세션 로그아웃을 보장할 수 없다. 모아는 미완료·결과 확인 필요 상태를 표시한다.

## 자원과 복구

각 조회 단계는 원본 자원 정책(`resource_policy.py`, 해시 고정)의 API 프로필 안에서 실행한다. 1,536MiB RSS 검사·180초 단계 제한·전역 직렬 잠금·소유 프로세스 정리를 유지한다. 단계 진입 점검에 약 15초가 걸리며 그대로 둔다(2026-11-04 결정). 로컬 복구 파일은 소유자 전용이며 완료 응답 유실을 복구하는 동안만 결과를 보관한다. 은행 로그인을 재실행하는 대신 이미 생성한 완료 결과만 재전송한다.

## 독립 스키마

`tools/mac-bank-runner/schema*.sql`은 주 Drizzle journal과 분리한 모듈 SQL이다. 각 버전을 한 트랜잭션에서 적용하고 `mac_bank_runner_schema_migrations`에 버전과 파일 SHA-256을 함께 기록한다. 기존 은행 마이그레이션 0068·0069와 `__drizzle_migrations`에는 기록하지 않는다.

| 버전 | 파일 | 내용 |
| --- | --- | --- |
| v1 | `schema.sql` | 실행기 grant·작업 표, 철회·불변성 트리거 |
| v2 | `schema-v2.sql` | 본인 연결 만료 시각 NULL 허용(`until_revoked`) |
| v3 | `schema-v3.sql` | 암호화 로그인 정보, 작업의 로그인 정보 버전·일회 전달 시각, 동의 v1·v2 |
| v4 | `schema-v4.sql` | 동의 v3 허용, 로그인 정보 전달 트리거가 동의 v2·v3을 받게 교체(2026-11-04) |

API는 v4가 기록되어 있어야 저장소를 준비된 것으로 본다. 배포 순서는 모듈 스키마 → API/web → 실행기 업그레이드다.

```sh
SHA=$(shasum -a 256 tools/mac-bank-runner/schema-v4.sql | cut -c1-64)
{ cat tools/mac-bank-runner/schema-v4.sql
  printf "\nINSERT INTO public.mac_bank_runner_schema_migrations(version, sql_sha256) VALUES ('mac-bank-runner-v4', '%s');\n" "$SHA"
} | docker exec -i family-memory-ai-postgres-1 sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1 --single-transaction -q'
```

## 운영 확인

웹/API 이미지와 OTA 번들을 각각 검증한다. 버튼의 요청 저장, Mac claim, 은행 로그인, 인증 대기, 실제 관찰 저장은 다른 증거다. 합성 관찰의 저장 테스트를 실제 은행 조회 성공으로 보고하지 않는다. 은행 접촉은 최소로 하고, 은행 폼 제출을 포함하는 시험은 사용자가 직접 실행한다.

기준값(2026-11-04 21:41 실제 조회): 버튼 → claim 2.7초, 실행 37.4초(자원 점검 약 15초 포함), 총 40.1초. 통장 1건·중도금 대출 1건이 저장됐고 계좌 지문·금액·만기는 같은 날 Codex 조회 결과와 같았다. Codex 경로의 성공 2건은 총 119.8~123.6초(실행 113초)였다.

## 이력

- 2026-11-03: Codex App Server + native Computer Use(`cua_repl`)로 Aside 앱을 AX로 조작하는 경로를 만들었다. 모델이 매번 판단해 느리고(실행 113초) 결과가 일정하지 않았으며(10건 중 성공 2건) 모델 비용이 들었다.
- 2026-11-04: `aside repl` 고정 절차로 교체했다(27b5ace). 실제 실행 네 번 만에 성공했고, 실패마다 원인을 고쳤다: 로그인 결과 판정이 은행 레이어를 놓침(f7b5945), 'ID 로그인' 안내창 [확인](6245106), 대출 탭 판별(73ba665). 같은 날 Codex 경로·엔진 스위치를 지우고 조회 동의를 v3으로 올렸다. Codex 코드가 필요하면 73ba665 이전에서 되살린다.
- 기각한 대안: 컨테이너에서 `aside repl --host`(컨테이너에 Aside 로그인 정보가 들어가고 원격 호출이 Aside 서버를 거친다), Mac 웹훅 서버(새 포트·토큰·비밀번호 평문 전달·API 재배포 중 결과 유실 처리가 필요하다), 컨테이너 → `aside mcp`(stdio 전용이고 CLI가 macOS 전용이며, 중계하면 로그인된 브라우저 전체가 컨테이너에 열린다).
