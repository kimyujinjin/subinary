# 거래 반영 상태·편집·환율 근거 개선

## 작업 범위와 기준

운영에 반영한 `9596599f0e694aac4971a3e3a6981eaad236c18f`에서 분리한
`fix/transaction-ux-followup` 작업 트리의 로컬 변경이다. 이 후속 변경은 아직 운영에
배포하거나 커밋하지 않았다. 원본의 staged 222개와 `fma-dot-card-quality` clean 기준은
보존한다. 새 의존성 설치·DB 마이그레이션·보존 정책 변경·모델 호출은 없다.

별도 `fix/parser-deploy-concurrency` 작업 트리는 `ef7a2b8`의 파서 유지보수 도구에만
배포 경합 보호를 보완한다. 이 구형 기준 전체를 제품 이미지로 배포하면 안 된다.

## 동작

- 문자 파싱과 거래 반영을 구분한다. 실제 `source_event_id` 연결이 있을 때만 반영을
  확인한다. 승격된 거래의 확인필요·중복의심 상태도 별도로 안내한다.
- 원문·금액 없는 `GET /v1/card-sms-events/:id/posting`은 기존 수신자·활성 멤버십
  경계를 유지한다. `posting=unposted` 목록은 기존 실패·격리 검토함과 중복하지 않는다.
- 환율 대기는 현재 정확한 키의 스냅샷 부재만 말한다. 과거 잡의 실패 원인을 복원하거나
  자동 복구 시점을 약속하지 않는다. 접수 후 상태 조회 실패를 재수집으로 처리하지 않는다.
- 금액·날짜 편집은 유효성 오류를 표시하고, 저장 성공 후 종료한다. 실패 시 입력을 보존한다.
  동기 잠금으로 반복 클릭을 막고, 닫힌 세션의 늦은 콜백을 무시한다.
- 목록 밖 딥링크 단건 캐시를 가구별로 분리하고 변경 응답으로 즉시 갱신한다.
  앞서 시작한 GET이 새 값을 덮지 않도록 취소·무효화한다.
- 모바일의 미저장 변경 확인, 저장 중 닫기 안내, native back의 최상위 모달 처리와
  browser popstate의 세션 정리를 추가한다. 날짜 입력은 기존 기기 시간 의미를 유지하고
  라벨에 명시한다.
- 외화 근거는 거래에 실제 연결된 불변 스냅샷에서 가져온다. ECB는 공급자·버전·공식 URL·
  관측 속성과 원관측 교차환율 계산까지 확인한다. 수동 보충·기타 공급자는 확인 가능한
  수준으로만 표시한다. legacy나 근거 누락은 기준일·출처를 꾸미지 않는다.
  취소의 적용 기준일을 취소일로 추정하지 않는다. 마스킹 거래에는 근거도 노출하지 않는다.

## 로컬 검증과 한계

- 최종 필수 CI 19/19, 1,953 통과·0 실패·기존 선택형 DB 통합 69개 건너뜀.
  전체 타입 검사, 공통 패키지 빌드, API SWC 빌드를 포함한다.
- 아키텍처 게이트는 기존 탐지·상한을 유지하며 8 ≤ 12로 통과한다.
- 웹은 기본 `next build`를 변경 없이 통과했다. 공유 의존성 심링크가 Turbopack의 프로젝트
  경계를 벗어나는 검증 환경 문제는 공개 소스 복사와 기존 의존성 APFS clone으로 해결했다.
  CSS 처리의 로컬 포트는 정상 승인 경로로 실행했다. 빌드는 합성 loopback 공개 URL을
  사용하므로 이 QA 산출물을 운영에 그대로 사용하면 안 된다.
- 실제 브라우저와 메모리 가짜 API로 기존 잘못된 완료 안내·무효 입력 닫힘·외화 설명을
  재현했다. 390×844와 320×568에서 오류/실패 시 입력 보존, 반복 클릭, 지연 저장,
  목록 밖 상세 갱신, 취소/뒤로가기, 환율 근거와 가로 넘침을 확인한다.
- 320px 내부 grid 넘침을 실제 요소 폭으로 발견해 거래 상세 범위에서 수정했다.
  문서 폭뿐 아니라 dialog clientWidth와 scrollWidth도 대조한다.
- 네이티브 뒤로가기 레지스트리는 합성 회귀로 검증했다. 실제 iOS/Android 기기,
  소프트 키보드, 전체 Nest/Redis/알림 및 실제 신규 거래의 종단 검증을 대신하지 않는다.
- 운영 읽기 진단의 구간은 `2026-10-30T16:06:36Z`부터 `2026-10-31T00:01:55Z`까지다.
  자연 수신 외화 승인 0건이라 신규 자동 환율 취득·승격은 미관찰이다. 취소는 이 조회
  범위에서 제외했다. API/worker는 조회 당시 `b8d9a3…`·revision `9596599…` healthy였다.

검증 영수증·합성 fixture·스크린샷은 저장소 밖 `fma-ux-validation`에 둔다. 초기 테스트
실패, 샌드박스 포트 거부와 최종 성공을 구분해 보존한다. API 분류 경합 테스트의 합성
driver는 새 LEFT JOIN의 실제 NULL projection을 채우도록 보완했고 기존 단언은 유지했다.

## 운영 반영 계획 — 실행 전 승인 단계

1. 현재 API·worker·web의 실제 이미지, 소스 기준, Compose 파일·환경 파일의 경로/순서를
   정상 설정 로딩으로 재확인한다. 값·원문을 직접 열지 않는다. 이 후속 코드와 비교해
   다른 운영 변경이 있으면 덮지 말고 조정한다.
2. 승인된 변경 경로만 검토 가능한 커밋/manifest로 고정한다. 전체 `git add`나 push는 하지
   않는다. 현재 단계에는 커밋과 배포 승인이 포함되지 않는다.
3. 검증된 운영 Linux 의존성과 기존 경량 배포 절차를 사용하되 최종 공개 운영 URL로 웹을
   다시 빌드한다. API·계약과 웹 산출물의 정확한 이미지 ID를 고정하고 후보 기동을 검증한다.
   새 worker 동작 변경은 없으며 worker 교체 필요 여부는 이미지 구성과 현재 운영 차이로 판단한다.
4. 서비스별 이전 이미지와 Compose 참조의 롤백을 먼저 확보한다. API의 새 읽기 계약을
   먼저 반영한 뒤 웹을 반영한다. health·이미지·비식별 오류만 확인하고 가짜 운영 거래를
   만들거나 큐를 재전송하지 않는다. DB 마이그레이션은 필요하지 않다.
5. 파서 보호는 별도 브랜치의 apply/flow/guard/test/doc 5파일만 검토해 유지보수 기준에
   반영한다. 기존 실행·미확정 영수증과 설정의 held 조건을 먼저 확인한다. clean 기준
   교체는 별도 승인 대상이며 예약 시각·알림·허용 파서 범위는 바꾸지 않는다.
6. 파서 간 독점 lock과 실행 직전 fingerprint를 검증해도 공유 lock을 쓰지 않는 다른 배포와
   Docker inspect→up 사이를 원자적으로 묶을 수는 없다. 기존 보류 절차를 지키고, 같은
   호스트의 배포자가 공용 lock을 사용하도록 합의하기 전까지 완전한 상호 배제를 주장하지 않는다.

운영 배포·재시작·예약/알림 변경·실데이터 쓰기·과거 거래 재계산·큐 재전송은 이 작업에서
수행하지 않는다. 신규 수신 관찰을 위한 별도 자동화도 만들지 않는다.
