# 카드 구분·합산 용돈 예산·Dot 연결 후속 기록

2026-10-28 KST. 전날 작업은 [기존 기록](finance-dot-2026-10-27.md), 설계는 [ADR-0034](../adr/0034-card-group-budget-and-dot-local-execution.md)를 참고한다.

**최신 상태 — 08:39 KST:** Dot이 연결된 Mac에서 품질 조회 명령을 실행해 FMA API 조회에 성공했다. 사용자 보고와 **가족 재무 오류 건수 조회** 작업의 완료 결과를 대조했다. 파싱 실패 0건·카드 소유자 불일치 0건, `fetchedAt=2026-10-27T23:39:07.959Z`다. 직접 MCP 도구 호출·분류 쓰기·예약 실행은 이 검증에 포함하지 않는다.

## 사용자 확인과 실제 변경

- 사용자는 삼성카드와 네이버 현대카드를 둘 다 사용하며, 두 카드를 기존 용돈 한도 하나로 합산하기를 선택했다.
- 본인 삼성 카드의 ID·발급사·끝번호는 유지하고 잘못된 별칭만 `삼성카드`로 수정했다. 기존 거래 74건과 예산 참조를 보존했다.
- 본인 네이버 현대카드를 별도로 등록했다. SMS 끝번호가 없어 번호를 추정하지 않았다. 같은 구성원·발급사 유일 매칭으로 기존 65건이 연결됐다.
- 복구 문자 거래 2건은 본인 현대카드에 연결하되 검토 상태를 유지했다. 삼성 과거 미연결 4건도 연결했고 그중 기존 제외 중복 2건의 제외 상태를 유지했다.
- 전체 512거래의 카드 ID·수정 시각 외 필드를 전후 대조했다. 배우자 카드·공용 토스카드 등록은 바꾸지 않았다.
- 2026년 8·9·10·11월의 용돈 예산 4개를 카드 묶음으로 정정했다. 기존 예산 ID·월·이름·한도를 보존했고 다른 예산 8개와 거래는 변경하지 않았다. 정정 이력 4건을 같은 DB 트랜잭션에 기록했다.
- 각 월의 API 사용액을 별도 SQL로 다시 계산해 모두 일치함을 확인했다. 기존 제외·자산 이동·통화·공개범위·취소 순액·서울 월 경계 규칙을 적용했다.

- API 전체 217개 통과, DB 환경 등이 필요한 47개는 기본 실행에서 생략했다. 예산 관련 29개는 격리 PostgreSQL의 실제 집계·0063→0064 업그레이드·동시 수정·충돌 롤백을 포함해 별도로 통과했다.
- worker 68개, 웹 277개, MCP 44개 테스트와 관련 타입 검사를 통과했다. 웹·모바일 모두 28경로 빌드에 성공했다. 외부 AI를 호출하지 않았다.
- 합성 390×844 모바일 화면에서 카드 선택, 공용·다른 소유자 선택 차단, 과거월 한도 잠금, 단일 카드→묶음 정정 요청과 가로 넘침 없음을 확인했다. [화면 근거](../evidence/budget-group-20261028/)의 금액·이름은 합성이다.
- 코드 커밋 `85e8ce6`, 이미지 `family-memory-ai/prod:budget-85e8ce6`, ID `sha256:8848846947a1bdfcbe78181989737cc340b69a6e008b28d972e910ff9f006208`.
- 마이그레이션 이력 65개, API·worker·웹 모두 healthy. 운영 Node 런타임의 모듈 로딩, 네트워크 없는 임시 웹 기동, 공개 도메인 주요 경로를 확인했다.

## Dot에서 확인한 경계

사용자가 Dot의 연결 컴퓨터가 온라인임을 확인했다. Dot에서 `family-finance` 도구가 보이지 않아 로컬 stdio 등록과 클라우드 도구 목록이 다름을 정정해 안내했다. 연결된 PC의 작업에서 실행하는 품질 조회 명령을 추가했다.

`/usr/local/bin/node /Users/soobeen/.local/share/family-memory-ai/mcp/check.cjs`

Dot이 만든 **가족 재무 오류 건수 조회** 작업에서 이 명령이 Mac에서 실행된 사실은 확인했다. 최초 결과는 종료 코드 1, `API_UNAVAILABLE`이었다. 같은 명령은 기존 로컬 실행 환경에서 성공했으므로 당시에는 Dot 품질 조회를 완료로 처리하지 않았다.

진단 버전은 실패 단계·시도 시각·프록시 설정 존재 여부·허용된 네트워크 오류 코드만 반환한다. 원시 오류·주소·인증 값을 출력하지 않으며, 가구 없음과 연결 실패를 구분한다. 사용자는 Dot에 직접 다시 실행을 요청하기로 했다. 다른 채팅에 대신 메시지를 보내지 않았다.

사용자가 요청한 Dot 재실행 기록을 읽기 전용으로 확인했다. 2026-10-28 08:27:58 KST(원본 `2026-10-27T23:27:58.495Z`)에 `stage=login`, `networkCode=ENOTFOUND`, `proxyConfigured=false`로 실패했다. 이 시점의 계정·집계 결과는 미확인이었다. 같은 PC의 일반 실행은 계속 성공했으므로 실행 환경의 네트워크 접근과 DNS를 다음 점검 대상으로 정했다.

08:39:07.959 KST에는 같은 Mac에서 네트워크 승인 후 DNS·TCP 443 연결·TLS 인증서 검증이 성공했고, `check.cjs`도 종료 코드 0으로 품질 결과를 반환했다. 사용자가 전달한 결과와 `wait_threads`의 동일 작업 완료 기록이 일치했다. 인증 파일 복사나 보안 설정 해제 없이 성공했다. 앞선 오류가 실행 환경의 네트워크 제한과 관련됐다는 판단을 뒷받침한다. 향후 무인 실행의 승인 유지나 다른 금융 도구 동작까지 검증한 것은 아니다.
